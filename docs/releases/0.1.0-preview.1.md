# FactsPDF 0.1.0-preview.1 — release notes (draft)

**Status: draft, not released.** These notes describe the candidate that the
current `main` builds. Nothing here publishes a package, grants a licence or
approves PDF pages. The [owner gates](#owner-gates-before-release) at the end
must be closed first.

## What this preview is

The first developer preview of FactsPDF: a .NET 10 library and CLI that
renders controlled HTML/CSS business-report templates to searchable PDF
without a browser. It targets invoices, inspection reports, quotes and status
summaries, in English and Chinese.

## Deliverables

| Component | Contents |

## Capabilities

The authoritative, searchable list is
[Can I Render](https://koalafacts.github.io/FactsPDF/); detailed notes per
feature are in [feature notes](../feature-notes.md).

- **Input:** inline `style` and embedded `<style>` rules, including
  `@media print`/`all`; documented selectors, specificity, `!important`,
  inheritance and `inherit`/`initial`/`unset`.
- **Elements:** headings, paragraphs, `div`/`section`/`article` panels, `span`,
  `br`, `pre`, `blockquote`, `hr`, lists to two levels, fixed-column tables and
  images.
- **Text:** English and Chinese with explicit TrueType fallback chains; normal,
  bold, italic and bold-italic roles; numeric and relative font weights; font
  sizes and keywords; line height; letter and word spacing; first-line indent;
  left/centre/right/justify and LTR start/end alignment; ASCII text-transform;
  underline/overline/strike-through in colour and dashed/dotted styles;
  optional font subsetting.
- **White space and wrapping:** `nowrap`, `pre`, `pre-line`, `pre-wrap`,
  `overflow-wrap:break-word`, `word-break:break-all`.
- **Lengths and colours:** `pt px mm cm in pc q`, `%`, `em`, `rem` where
  documented; hex, opaque `rgb()`/`hsl()`, 148 named colours and
  `currentColor`.
- **Boxes:** width, min/max width, height, min-height, padding, margins,
  `margin:0 auto`, `box-sizing`, backgrounds, solid/dashed/dotted borders,
  rounded corners, report-panel outlines and LTR logical properties.
- **Tables:** explicit column widths, `colspan`, paragraph and image cells,
  repeated headers, long rows continuing across pages, cell `vertical-align`.
- **Images:** baseline JPEG and static PNG with transparency; physical width
  and height with min/max constraints.
- **Pages:** automatic pagination; `break-before`, `break-after` and
  `break-inside:avoid` within documented limits; heading keeps; header and
  footer text, page numbers, styled page furniture with `{page}`/`{pages}`;
  A4/Letter, landscape, custom paper and margins; PDF title, author, subject
  and keywords.
- **Safety:** bounded resource limits, stable `FPDF` error codes, and a failed
  conversion never replaces an existing output file. The CLI reports the line
  and column of the HTML that caused a diagnostic, without echoing input text;
  `FactsPdfException.SourceOffset` carries the same position for SDK callers
  where one is known (otherwise -1), including text failures (a character no
  supplied font covers, an unbreakable word wider than the page, a line or
  paragraph too tall for the page) and patterned (dashed or dotted) borders too
  thin or too short to paint, which point at their element.
- **Robustness:** every untrusted input (HTML/CSS text, font bytes, image
  bytes) either renders a complete PDF or fails with `FactsPdfException`.
  Fixed-seed mutation fuzz tests run in CI, and a longer pre-release run of
  more than 570,000 mutated and generated inputs found one defect (a PNG preset
  dictionary), now fixed. Output is byte-identical across concurrent calls
  with shared fonts and under any current culture.
- **Developer experience:** a fluent, immutable and thread-safe SDK:
  `Pdf.Write().WithFonts(…).WithPage(…).ToBytes(html)`, with `ToStream`,
  `ToStreamAsync`, `ToBufferWriter` and atomic `ToFile`/`ToFileAsync` outputs.
  IntelliSense XML documentation for the whole public API ships in the NuGet
  package. Builds use the .NET recommended analyzers
  with warnings as errors.

## Not included

Arbitrary webpages, JavaScript, network loading, external stylesheets,
flexbox, grid, floats, positioning, `@page`, automatic table widths, `rowspan`,
nested tables, system fonts, synthetic bold/italic, complex shaping, RTL and
vertical text, transparency, gradients and SVG. The Node subprocess and
browser WASM integrations are experimental probes, not supported SDKs.

### Performance (provisional)

Linux x64 Native AOT on a shared GitHub Actions runner; medians of two batches.
These are observations, not an approved budget or guarantee.

| Case | Pages | Cold CLI run | Warm `Convert` | Warm allocation |
| --- | ---: | ---: | ---: | ---: |
| B00 (ASCII, built-in font) | 1 | 5.4–5.6 ms | 0.10 ms | 0.11 MB |
| B01 (Chinese, TrueType) | 1 | 17.7–18.1 ms | 1.4 ms | 1.6 MB |
| B02-100 (100 records) | 3 | 19.7–20.5 ms | 2.0 ms | 3.2 MB |

Cold runs include process start, font and input reads and writing the PDF.
Conversion time grows linearly with page count: on a 2-core development
container, a 20,000-row bordered table (1,001 pages, embedded subset font)
took about 3 s, and adversarial inputs at the default limits (a 990,000-character
paragraph, maximum nesting, worst-case selector matching) finish or fail with
their limit code within about 1 s.
Cold peak RSS was about 79 MB, which includes a launcher floor (see
[peak calibration](../acceptance/peak-calibration.md)).

Managed allocation per conversion is guarded by `AllocationBudgetTests` and is
being reduced step by step without changing output bytes (see the
[MVP roadmap](../mvp-roadmap.md)). So far: style computing makes at most one
box-style copy and one text-style copy per element (an element whose text style
does not change shares its parent's, and plain siblings share one tag-defaults copy), CSS parsing reuses source text instead of
copying it for every token and value, the page is tokenized once for both stylesheet collection and the document reader (into a token list each thread reuses, with open elements and their selector view tracked as values rather than one object each), a paragraph element keeps its runs and its one child in exact-size arrays, computing an element's style allocates no closure object, an element's classes are kept in a small list (shared when it has none, the attribute text itself when it has one), a style attribute without character references keeps no per-character position map (its positions follow from where its value starts), text wrapping reuses its glyph lists across paragraphs and reads each paragraph's glyphs without a reader object, table cells keep their measured lines as values in one exact-size array each, a fully embedded font is compressed once per `PdfFont`, the PDF is
built in a pooled buffer, and page content streams are written straight into it
from one reused builder, with most numbers formatted in place.
