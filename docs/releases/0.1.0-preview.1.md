# FactsPDF 0.1.0-preview.1 — release notes (draft)

**Status: draft, not released.** These notes describe the candidate that the
current `main` builds. Nothing here publishes a package, grants a licence or
approves PDF pages. The [owner gates](#owner-gates-before-release) at the end
must be closed first.

## What this preview is

The first developer preview of FactsPDF: a .NET library (for .NET 8, 9 and 10) and a .NET 10 CLI that
renders controlled HTML/CSS business-report templates to searchable PDF
without a browser. It targets invoices, inspection reports, quotes and status
summaries, in English and Chinese.

FactsPDF is licensed under the Apache License 2.0 and is free for any use,
including commercial. Paid commercial support is available from Koala Facts
Trading Pty Ltd.

## Capabilities

The authoritative, searchable list is
[Can I Render](https://koalafacts.github.io/FactsPDF/); detailed notes per
feature are in [feature notes](../feature-notes.md).

- **Input:** inline `style` and embedded `<style>` rules, including
  `@media print`/`all`; documented selectors (including the `:root`
  pseudo-class), custom properties and `var()` (with fallbacks; a reference
  without a value fails instead of being unset), specificity, `!important`,
  inheritance and `inherit`/`initial`/`unset`/`revert`/`revert-layer` (also
  from a `var()` fallback). Structural pseudo-classes
  (`tr:nth-of-type(even)`, `li:first-child`, `p:last-of-type`, `:empty`) and
  `:not()` with compound arguments match as in Chrome, and so do `body`, `html`
  and `:root` rules in pages that omit those tags. Strict CSS is the default;
  opt-in non-strict CSS (`WithStrict(false)`, CLI `--strict false`) drops CSS
  that is invalid per the specifications exactly as a browser does (unknown
  properties and at-rules, values a property cannot take, invalid selectors,
  syntax errors, `style` elements whose type is not CSS; an invalid `var()`
  substitution computes as `unset`) and
  reports each as a warning with the strict error's code and location, while
  valid but unsupported CSS still fails.
- **Elements:** headings, paragraphs, `div`/`section`/`article` panels (and
  `header`, `footer`, `main`, `nav`, `aside`, `hgroup`, `search`, which render like `div`, and
  `address`, an italic `div`; `dl`/`dt`/`dd` description lists, with the
  default `dl` margins and `dd` indent), `span`,
  the inline text elements `code`, `kbd`, `samp` (in the supplied regular font)
  and `var`, `cite`, `dfn` (italic), `time`/`data` (their `datetime`/`value`
  kept as metadata), `abbr` (dotted underline with a `title`), `q` (in quotation marks), `bdi` (like `span`), `template` (dropped with its inert contents), `script` (dropped with its data, never run), named `meta` such as viewport and Open Graph (accepted, changes nothing), metadata `link` such as icon, canonical and preconnect (accepted, never fetched; stylesheet links still fail), one `base` in head (accepted, relative URLs are still not resolved), `br`, `pre`, `blockquote` (and `figure`, which renders like it, with
  `figcaption` like `div`), `hr`, lists to two levels (`menu` like `ul`; the HTML `type` attribute picks the marker, as in `<ol type="a">`), fixed-column tables,
  images, and inline `svg` logos and icons drawn as PDF vector paths. An `img` or
  `svg` is an inline replaced box by default, as in Chrome: it sits on its line's
  baseline (keeping the descender gap below a logo), takes `vertical-align`
  (`baseline`, `middle`, `top`, `bottom`, `text-top`, `text-bottom`, lengths and
  percentages), wraps as one unit and is clickable inside a link;
  `display:block` keeps the block layout. Inline svg paints translucent
  colours, `fill-opacity`, `stroke-opacity` and `opacity` over non-overlapping
  shapes with PDF constant alpha.
  `dir="ltr"` is accepted on any element; other directions still fail. The `hidden`
  attribute removes an ordinary report block like `display:none`. Links accept
  `target="_blank"` and `rel="noopener noreferrer"` (and the other hyperlink types).
- **Text:** English and Chinese with explicit TrueType fallback chains; normal,
  bold, italic and bold-italic roles; numeric and relative font weights; font
  sizes and keywords; line height; letter and word spacing; first-line indent;
  left/centre/right/justify and LTR start/end alignment; ASCII text-transform;
  underline/overline/strike-through in colour and dashed/dotted styles (also
  through the legacy `-webkit-text-decoration` shorthand and longhands);
  optional font subsetting.
- **White space and wrapping:** `nowrap`, `pre`, `pre-line`, `pre-wrap`,
  `overflow-wrap:break-word` (also as the legacy `word-wrap`), `word-break:break-all`.
- **Lengths and colours:** `pt px mm cm in pc q`, `%`, `em`, `rem` where
  documented; hex (including `#rgba`/`#rrggbbaa`), `rgb()`/`hsl()` (including CSS Color 4 `rgba()`/`hsla()` aliases, comma or `/` alpha and `deg`/`grad`/`rad`/`turn` hues), 148 named colours, `transparent` and
  `currentColor`. Translucent colours composite with PDF constant alpha on text, backgrounds,
  borders, outlines, decorations and list markers, as in Chrome.
- **Overflow, clipping and line breaking:** lines break where Chrome breaks them (the Unicode line breaking algorithm with Chrome's tailoring: hyphens before digits, slashes, CJK kinsoku, `word-break:keep-all|break-all`, `line-break`), `white-space` takes every value including `break-spaces` and applies to inline elements, tabs follow `tab-size`, and text, boxes and images wider than their box overflow it instead of failing (content wider than the page prints scaled down, up to 1.5 times). `overflow:hidden|clip` clips to the padding box, `text-overflow:ellipsis` ends overflowing lines and `visibility:hidden|collapse` keeps the layout and paints nothing; `overflow:scroll` and an overflowing `overflow:auto` fail `FPDF1201` because Chrome prints their scrollbars.
- **Block margins:** vertical margins collapse as in CSS 2 on every block box
  (siblings, parent and first or last child, empty blocks; padding and borders keep
  them apart), are truncated at unforced page breaks and kept after forced ones, and
  stay inside table cells, flex items and grid items; `ul`, `ol`, `menu`, `li` and
  `table` take vertical margins (`margin:20pt 0` on a table works), lists have
  Chrome's 1em user-agent margin (none when nested) and table-cell paragraphs take
  padding. A nonzero horizontal table margin and a percentage vertical margin on a
  list or table fail `FPDF1201`.
- **Table and list placement:** lists in table cells (markers, margins that stay inside the
  cell, `li{display:flex}` key/value rows, automatic column widths; a row with a list moves
  whole to the next page), tables as flex and grid items (sized by their width and content,
  stretching their body rows when the line is taller), tables after inline text, in list
  items and after an open `p` (which the table closes), and `min-width`/`max-width` on a
  table (`min-width` wins). An author `padding-left` on `ol`/`ul`/`menu`, zero included,
  replaces the list's 40px user-agent padding as in Chrome, so `*{margin:0;padding:0}` resets leave list items
  at the left edge. A row with a list that must split across pages, a marked item that starts
  with a table and a `max-width` below explicit column widths fail explicitly.
- **Nested tables, footer-only tables and free-text links:** a table directly in a `td`/`th` (a
  colspan cell holding a table of fixed-width cells) lays out as cell content with automatic
  widths, and the outer row grows to fit and moves whole to the next page; a table may be only
  a `tfoot` (invoice totals), a `thead` and a `tfoot`, or have its `tfoot` before the `tbody`
  (laid out after it); in non-strict mode an `a href` that is not an absolute HTTPS or mailto URL
  (free text, a relative path) draws as an ordinary link with no annotation and a warning. Tables
  nested more than three levels (`FPDF1003`), a table outside a cell's direct content, an inner
  table wider than its cell, a second `tfoot` or `tbody` and a `thead` after the body fail
  explicitly; Chrome splits an outer row between inner rows and repeats a `tfoot` on every page, which
  FactsPDF does not.
- **The `font` shorthand:** `font:12pt F`, `font:bold italic 14px/2 F`, `font:16px/20px F`,
  percentage, `em` and keyword sizes, `font:inherit` and the other CSS-wide keywords, in
  stylesheets, inline `style` and `var()`. It expands at the declaration's position into
  `font-style`, `font-weight`, `font-size` and `line-height` and resets the ones it does not
  mention to `normal`, so a later `font:12pt F` overrides an earlier `font-weight:bold` and a later
  `font-weight:bold` still overrides the earlier `font`, as in Chrome; the page equals the one with
  the longhands written out. `font-variant`, `font-stretch` and the family list are validated and
  dropped as before. `small-caps`, stretch keywords, `oblique`, numeric weights that are not a
  hundred, a zero size and the system font keywords (`caption`, `icon`, `menu`, `message-box`,
  `small-caption`, `status-bar`) fail `FPDF1202`; a shorthand invalid per the specifications fails
  `FPDF1202` in strict mode and is dropped with a warning in non-strict mode. Before, every `font`
  declaration failed `FPDF1201`.
- **Browser defaults:** every supported element starts from Chrome's user-agent
  stylesheet, the lowest cascade origin below every author rule: the 8px `body`
  margin, 1em `p`, `pre` and `dl` margins, `h1` to `h6` at 2 to .67em with their
  margins and bold (like `b`, a heading needs a bold font chain or `font-weight:normal`),
  1em 40px `blockquote` and `figure`, 40px list padding with hanging markers (no
  marker gutter, so `ul{padding:0}` puts the text at the container's edge), 1px cell
  padding with middle alignment, Chrome's `hr` bevel, `#0000ee` links and `big`, and
  `line-height:normal` from the font's own metrics. `*{margin:0;padding:0}` resets
  keep working; `body{margin:0}` is a real reset now. A table has no 2px cell spacing
  yet. The element defaults are checked against Chrome in every test run
  ([user-agent stylesheet](../css-stylesheets.md#user-agent-stylesheet)).
- **Boxes:** width, min/max width, height, min-height, padding, margins,
  `margin:0 auto`, zero `<html>` margins and `<html>` padding (so `html{margin:0;padding:0}` resets render), zero margins/padding and transparent backgrounds on inline text (so normalize.css `a{background-color:transparent}` renders), zero margins on `li` and table rows, groups, columns and cells, zero margins on `ul`, `ol`, `table` and `br` and zero padding on table rows, groups, columns and `br` (so `*{margin:0;padding:0}` renders list and table pages), `box-sizing` (also as `-webkit-`/`-moz-box-sizing`, and accepted on
  `<html>`, inline text, `<br>` and table parts, with a `border-box` table width including its padding and borders, so `*{box-sizing:border-box}` resets render; likewise the legacy
  `-webkit-`/`-moz-`/`-ms-`/`-o-` spellings of `border-radius`, `box-shadow`,
  `transform`, `filter`, `clip-path` and `backdrop-filter`), backgrounds (including the `background: none` reset), solid/dashed/dotted borders
  (including `border-color: transparent`, which keeps the width and paints
  nothing, and `border-style: hidden`, which equals `none`), rounded corners, report-panel outlines (an `outline:none` reset on any other element changes nothing) and LTR logical properties.
- **Flex rows:** single-line, row-direction `display:flex` on report panels, list
  items and `body` (header bars, `li` label/value rows): `flex`, `flex-grow`,
  `flex-shrink`, `flex-basis`, `justify-content`, `align-items`/`align-self`
  (including `baseline`), `gap`/`column-gap`, `auto` margins and `order`. A row
  is kept whole on one page; `flex-wrap:wrap` and column directions fail.
- **Generated content:** `::before`/`::after` (and `:before`/`:after`) with
  string `content`, as inline text or as block boxes such as flex divider lines;
  `counter()`, `attr()` and `url()` content fail.
- **Grid columns:** `display:grid` with `grid-template-columns` of lengths,
  percentages, `fr` and `auto` tracks, auto-placed items in auto-sized rows,
  gaps, `justify-content`, `justify-items`/`justify-self` and
  `align-items`/`align-self`; pages break between rows. `repeat()`, `minmax()`
  and explicit placement fail.
- **Selectors, cascade and values from modern CSS:** the sibling combinators `+` and `~`;
  CSS nesting (`&`, relative selectors, nested `@media print` and `@layer`); `@layer` with
  named, anonymous, statement and dotted forms, the `!important` reversal and `revert-layer`;
  `calc()`, `min()`, `max()`, `clamp()` and `vw`/`vh`/`vmin`/`vmax` (against the page area);
  `lab()`, `lch()`, `oklab()`, `oklch()` and `color()` converted to sRGB as Chrome writes
  them; animations shown at their time-zero keyframe state; the `width`/`height` attributes
  of `img` and the `width` attribute of tables and cells as presentational hints; `on*`
  attributes accepted and ignored; a slash on a non-void tag ignored; `padding:auto` and
  percentage border widths named as invalid CSS. Chrome-verified; the unsupported rest
  (states between keyframes, `min()` mixing a percentage and a length, negative margins,
  intrinsic widths) fails with a precise code.
- **Initial-value declarations:** `position:static`, `float:none`, `clear:none`,
  `overflow:visible` (and `-x`/`-y`), `visibility:visible`, `z-index:auto` and
  `opacity:1`, `mix-blend-mode:normal`, `isolation:auto`, and `none` for
  `box-shadow`, `text-shadow`, `transform`, `filter`, `background-image`,
  `clip-path` and `backdrop-filter`, and the font tuning resets
  `font-feature-settings` (also `-webkit-`/`-moz-`), `font-variation-settings`,
  `font-variant-ligatures`, `font-variant-numeric` and `font-stretch` at `normal`,
  `font-optical-sizing:auto` and `font-size-adjust:none` (Tailwind preflight),
  `font-variant` and its `-caps`, `-east-asian`, `-alternates` and `-position`
  longhands at `normal`, `font-language-override`, `font-variant-emoji` and
  `font-palette` at `normal`, `text-emphasis` and `text-emphasis-style` at `none`,
  `direction:ltr`, `unicode-bidi:normal`, `writing-mode:horizontal-tb`,
  `text-orientation:mixed` and `text-combine-upright:none`, the multi-column resets
  `column-count`, `column-width` and `columns` at `auto`,
  `column-span`, `column-rule` and `column-rule-style` at `none` and `column-fill:balance`,
  `text-overflow:clip`, `line-clamp` and `-webkit-line-clamp` at `none`,
  `box-decoration-break` and `-webkit-box-decoration-break` at `slice`,
  `rotate`, `scale`, `translate` and `perspective` at `none`, `transform-style:flat`,
  `mask`, `mask-image`, `-webkit-mask`, `-webkit-mask-image` and `shape-outside` at
  `none`, `hanging-punctuation:none`, `hyphenate-character` and
  `text-underline-position` at `auto`, `text-spacing-trim:normal`,
  `background-attachment:scroll`, `background-blend-mode:normal`,
  `background-origin:padding-box`, `container-type:normal`, `container:none`,
  `aspect-ratio:auto`, `mask-repeat:repeat`, `mask-size:auto`, `mask-origin` and
  `mask-clip` at `border-box`, `mask-mode:match-source`, `mask-composite:add`,
  `mask-type:luminance`, `animation-composition:replace`,
  `animation-timeline` and `view-timeline-inset` at `auto`, `animation-range` and
  its `-start`/`-end` longhands at `normal`, `scroll-timeline`, `view-timeline`,
  their `-name` longhands, `timeline-scope`, `view-transition-name` and
  `view-transition-class` at `none`, `scroll-timeline-axis` and
  `view-timeline-axis` at `block`, `anchor-name`, `anchor-scope`, `position-area`,
  `position-try`, `position-try-fallbacks` and `overlay` at `none`,
  `position-try-order:normal`, `interpolate-size:numeric-only`,
  `reading-flow:normal`, `field-sizing:fixed`, `dynamic-range-limit:no-limit`,
  `caret`, `caret-animation` and `caret-shape` at `auto`, `text-wrap-style` and
  `text-box-edge` at `auto`, `text-box-trim:none`, `text-box`, `paint-order`,
  `math-style` and `math-shift` at `normal`, `contain-intrinsic-size` and its
  four longhands at `none`, `transform-box:view-box`, the box offsets
  (`top`, `right`, `bottom`, `left`, `inset` and logical insets) at `auto`,
  `border-image` and `border-image-source` at `none`, `border-collapse:separate`,
  `border-spacing` at one or two zero lengths, `empty-cells:show`, `caption-side:top`, `offset-path:none`, `offset-rotate:auto`,
  `offset-anchor:auto`, `initial-letter:normal`, `text-emphasis-color:currentcolor`,
  `vertical-align:baseline`
  outside table cells, and
  `zoom:normal` (or `1`), `contain:none`, `content-visibility:visible` and `auto` for
  `line-break`, `text-justify` and `image-rendering`, are accepted and change nothing, so stylesheets that
  reset them render; any other value of these properties still fails with
  `FPDF1202`.
- **Interaction-only declarations:** `cursor`, `pointer-events`, `user-select`
  and `resize` accept any single keyword value (`cursor:pointer`,
  `user-select:none`, ...) and change nothing, since a PDF page has no pointer;
  `-webkit-`/`-moz-`/`-ms-user-select` are aliases of `user-select`, and
  `-webkit-user-drag`, `-webkit-touch-callout` and `-ms-overflow-style`
  keywords, and the aural `speak` keywords icon-font stylesheets write
  (`speak:none`), are dropped likewise, as are `font-synthesis:none` (and its
  `-weight`, `-style`, `-small-caps` and `-position` longhands at `none`) and
  `text-decoration-skip-ink` and `font-kerning` at `auto` or `none` and the legacy
  `text-decoration-skip` / `-webkit-text-decoration-skip` at `none`, `auto` or
  `objects`, and `quotes` at `auto`, `none`, `match-parent` or pairs of strings
  (no `q` element or quote content is accepted);
  cursor images and other values fail with `FPDF1202`.
- **`font-family` lists:** a well-formed `font-family` list (names, quoted
  names and generic families) no longer fails the whole conversion with
  `FPDF1201`. Fonts are still never discovered or matched by name, so the text
  uses the fonts you supply (or Courier), as a browser falls back when none of
  the named families is installed; malformed lists fail with `FPDF1202`.
- **Legacy `word-break:break-word`:** Bootstrap's `.text-break` and many
  copied stylesheets write `word-break:break-word`; it used to fail with
  `FPDF1202`. It now wraps an over-long token exactly like
  `overflow-wrap:break-word` (a fitting word still moves whole), even when
  `overflow-wrap` is `normal`, and inherits like the other `word-break` values.
- **`overflow-wrap:anywhere`:** report stylesheets that protect narrow table
  cells with `.ledger td { overflow-wrap: anywhere; }` used to fail with
  `FPDF1202`. `anywhere` (and `word-wrap:anywhere`) is now accepted wherever
  `break-word` is and wraps an over-long token exactly like it; the two differ
  only in min-content sizing, which FactsPDF never computes.
- **Print colour adjustment:** `print-color-adjust`, `-webkit-print-color-adjust`,
  the deprecated `color-adjust` and the non-standard `background-color-adjust`
  accept `exact` or `economy` and change nothing:
  colours and backgrounds are always painted exactly as declared.
- **Tab width:** `tab-size` and `-moz-tab-size` (Tailwind preflight) accept a
  non-negative number or length and change nothing, since no tab stop reaches the
  page; other values fail with `FPDF1202`.
- **Font smoothing hints:** `text-rendering`, `-webkit-font-smoothing` and
  `-moz-osx-font-smoothing` accept their keywords and change nothing: a PDF
  viewer chooses how to rasterise glyphs.
- **Text size adjustment:** `text-size-adjust`, `-webkit-text-size-adjust` (also `-ms-`/`-moz-`)
  (`html{-webkit-text-size-adjust:100%}` in normalize.css) accept `auto`, `none`
  or a percentage and change nothing: a PDF page is never inflated.
- **Appearance resets:** `appearance`, `-webkit-appearance` and `-moz-appearance`
  accept their keywords and change nothing: no native form controls are drawn.
- **Back face and touch hints:** `backface-visibility` (also `-webkit-`) and a
  single `touch-action` keyword change nothing: no 3D transform or touch input
  reaches a PDF.
- **Compositor hints:** `will-change` (`auto` or a list such as
  `transform, opacity`) changes nothing: a written PDF page never animates.
- **Transform origins:** `transform-origin` (such as `top left` or
  `50% 50% 0`) and `-webkit-transform-origin` change nothing: no transform
  other than `none` is accepted, so no box pivots.
- **Transitions:** `transition` (such as `all .2s ease` or `none`), its
  longhands and their `-webkit-` spellings change nothing: a written PDF page is never restyled.
- **Animations:** `animation` (such as `spin 1s linear infinite`), its
  longhands and `@keyframes` rules change nothing: a PDF page shows no keyframe.
- **Scrolling:** `scroll-behavior`, `overscroll-behavior`, `overflow-anchor`,
  `-webkit-overflow-scrolling` and `scrollbar-width` keywords, and `scroll-margin`
  and `scroll-padding` offsets (with their side and axis longhands) and
  `scroll-snap-type`, `scroll-snap-align` and `scroll-snap-stop` keywords, change
  nothing: a PDF page never scrolls.
- **Colour-scheme hints:** `color-scheme` and `forced-color-adjust` change
  nothing: a PDF page has no dark mode or forced high-contrast palette.
- **Screen-only UI colours:** `-webkit-tap-highlight-color`, `caret-color`,
  `accent-color`, `scrollbar-color` and `scrollbar-gutter` change nothing: a PDF
  page has no caret, form widget, tap flash or scrollbar.
- **Tables:** explicit column widths, or automatic column widths from the cell
  content and any `col` or cell widths when a table does not give every `col` a
  width, `colspan`,
  `th` and `td` cells in any row, row and row group background colours,
  table captions, `border-collapse:collapse` with Chrome's border conflict rules, and
  `th` text centred by default as in Chrome (a header without `text-align` now renders centred),
  paragraph and image cells,
  repeated headers, `tfoot` total rows after the body, long rows continuing across pages, cell `vertical-align`.
  Stylesheets that restate `thead{display:table-header-group}`, `tbody`/`tfoot{display:table-row-group}`,
  `tr{display:table-row}` or `td,th{display:table-cell}` render unchanged, and so do
  `tr{break-inside:avoid}` and `page-break-inside:avoid` on rows that fit a page; a kept
  row taller than a page starts on a fresh page and continues there, as Chrome prints it.
- **Images:** baseline JPEG and static PNG with transparency; physical width
  and height with min/max constraints.
- **Pages:** automatic pagination; `break-before`, `break-after` and
  `break-inside:avoid` (also `page-break-inside`) on panels, paragraphs, headings, lists,
  list items and tables with any block content: a box that does not fit the rest of the page
  moves whole to the next page, a box taller than a page moves and then breaks normally,
  and a box that starts a page or whose first break is forced stays, as Chrome prints it
  (**changed:** the kept-card limits of one to eight flat top-level paragraphs and the
  one-page ceiling are gone; flex and grid containers, inline elements and table cells still
  fail `FPDF1201`); heading keeps; `orphans` and
  `widows` placed as Chrome places them, including table cells, with the CSS
  initial value 2 for every paragraph (**changed:** a page no longer ends with
  a paragraph's lone first line or starts with its lone last line, and a
  `break-after:avoid` heading stays when two lines of its paragraph fit after
  it; `orphans:1;widows:1` restores the old line breaks); header and
  footer text, page numbers, styled page furniture with `{page}`/`{pages}`;
  A4/Letter, landscape, custom paper and margins; CSS `@page` size, per-side
  margins and top/bottom margin boxes with `counter(page)`/`counter(pages)`;
  PDF title, author, subject and keywords.
- **Safety:** bounded resource limits, stable `FPDF` error codes, and a failed
  conversion never replaces an existing output file. The CLI reports the line
  and column of the HTML that caused a diagnostic, without echoing input text;
  `FactsPdfException.SourceOffset` carries the same position for SDK callers
  where one is known (otherwise -1), including text failures (a character no
  supplied font covers, an unbreakable word wider than the page, a line or
  paragraph too tall for the page) and patterned (dashed or dotted) borders too
  thin or too short to paint, which point at their element; exceeding the page
  limit (`FPDF1303`) points at the paragraph, list item, heading, panel, image
  or table that needed the extra page, and running out of display commands
  or output bytes (`FPDF1401`) while a box, list marker or text decoration is
  laid out or painted points at that paragraph, list item, heading, table cell
  or box; so do a too-short dashed or dotted text decoration and a link with
  no visible rectangle (`FPDF1302`). The nesting limit (`MaxDepth`,
  `FPDF1003`) is checked while the page is read, so a deeply nested flood
  fails at the first element past the limit instead of after the whole page
  is tokenized; the CSS nesting limit (`MaxCssSyntaxDepth`, `FPDF1205`) is
  likewise checked while each stylesheet or style attribute is tokenized, and
  a CSS node flood over `MaxCssSyntaxNodes` (`FPDF1205`) stops soon after
  the limit instead of after the whole style element is tokenized; a CSS rule
  flood over `MaxCssSelectors` (`FPDF1205`) stops at the first rule past the
  budget. Custom properties cost each element only its own declarations
  (thousands of `:root` tokens no longer cost a copy per declaring element),
  a page may use at most `MaxCssCustomProperties` (default 4,096) distinct
  custom property names, and reference chains and the nesting of substituted
  values are bounded by `MaxCssSyntaxDepth` however they are resolved (all
  `FPDF1205`).
- **Robustness:** every untrusted input (HTML/CSS text, font bytes, image
  bytes) either renders a complete PDF or fails with `FactsPdfException`.
  Fixed-seed mutation fuzz tests run in CI, and a longer pre-release run of
  more than 570,000 mutated and generated inputs found one defect (a PNG preset
  dictionary), now fixed. Output is byte-identical across concurrent calls
  with shared fonts and under any current culture.
- **Runtimes:** the library runs in .NET 8, .NET 9 and .NET 10 apps (and .NET 11
  through the `net10.0` asset); the test suite runs on each (allocation budgets
  and compressed-byte pins on .NET 10 only). Output is byte-identical for the
  same input, options and .NET runtime version; different .NET versions may
  produce different bytes (for example in compressed streams: fonts, images,
  page content, since they ship different zlib builds) with the same rendered
  content. Byte parity and hash-pinned tests are authoritative on .NET 10 only.
- **Developer experience:** a fluent, immutable and thread-safe SDK:
  `Pdf.Write().WithFonts(…).WithPage(…).ToBytes(html)`, with `ToStream`,
  `ToStreamAsync`, `ToBufferWriter` and atomic `ToFile`/`ToFileAsync` outputs.
  IntelliSense XML documentation for the whole public API ships in the NuGet
  package. Builds use the .NET recommended analyzers
  with warnings as errors.

## Not included

Arbitrary webpages, JavaScript, network loading, external stylesheets,
multi-line or column flexbox, grid placement beyond auto-placed columns, floats, positioning, `@page` selectors and side/corner margin boxes, `table-layout`, `rowspan`,
tables nested more than three levels, system fonts, synthetic bold/italic, complex shaping, RTL and
vertical text, transparency, gradients and SVG. The Node subprocess and
browser WASM integrations are experimental probes, not supported SDKs.

### Performance (provisional)

Linux x64 Native AOT on a shared GitHub Actions runner; medians of two batches.
These are observations, not an approved budget or guarantee.

| Case | Pages | Cold CLI run | Warm `Convert` | Warm allocation |
| --- | ---: | ---: | ---: | ---: |
| B00 (ASCII, built-in font) | 1 | 5.4–5.6 ms | 0.10 ms | 0.11 MB |
| B01 (Chinese, TrueType) | 1 | 17.7–18.1 ms | 1.4 ms | 1.6 MB |
| B02-100 (100 records) | 3 | 19.7–20.5 ms | 2.0 ms | 3.2 MB |

Cold runs include process start, font and input reads and writing the PDF.
Conversion time grows linearly with page count: on a 2-core development
container, a 20,000-row bordered table (1,001 pages, embedded subset font)
took about 3 s, and adversarial inputs at the default limits (a 990,000-character
paragraph, maximum nesting, worst-case selector matching) finish or fail with
their limit code within about 1 s.
Cold peak RSS was about 79 MB, which includes a launcher floor (see
[peak calibration](../acceptance/peak-calibration.md)).

Managed allocation per conversion is guarded by `AllocationBudgetTests` and is
being reduced step by step without changing output bytes (see the
[MVP roadmap](../mvp-roadmap.md)). So far: style computing makes at most one
box-style copy and one text-style copy per element (an element whose text style
does not change shares its parent's, and plain siblings share one tag-defaults copy), CSS parsing reuses source text instead of
copying it for every token and value, a style attribute's declarations are compiled without iterator or enumerator objects or growing term lists (and a style text repeated on later elements of the same page is not parsed again; its elements reuse the first compile's declarations, seen at their own order and offset, without a new object per declaration, and an element whose box declarations and box inputs repeat an earlier element's shares that element's computed box instead of a copy), the page is tokenized once for both stylesheet collection and the document reader (into a token list each thread reuses, with open elements and their selector view tracked as values rather than one object each, and each start tag's attributes kept in one exact-size array rather than a hash map), a paragraph element keeps its runs and its one child in exact-size arrays, a paragraph is its own child in the read tree without a wrapper object and keeps its source offset and anonymous flag in one field, only tokens of start tags with attributes store an attribute map (and only those with a style attribute store its source offsets and its compiled declarations, so the cascade needs no map from tag offset to declarations), every other token is 32 bytes, computing an element's style allocates no closure object, an element's classes are kept in a small list (shared when it has none, the attribute text itself when it has one), a style attribute without character references keeps no per-character position map (its positions follow from where its value starts), character references are decoded into one buffer without a builder or a string per reference, the box and border shorthands expand into their sides without a side, edge or term array per declaration, a three-digit `#rgb` color is read without building a `#rrggbb` string, a declaration block collects its expanded shorthands in one reused list per thread instead of a list that grew by doubling, the CSS parser reads the tokenizer's reused token list instead of a copy of every stylesheet's and style attribute's tokens, and each declaration collects its values in a reused list instead of a new list that grew by doubling, text wrapping reuses one line wrapper and its glyph lists across paragraphs and reads each paragraph's glyphs without a reader object, table cells keep their content items inline (a list of their own only from the second item) and their measured lines as values in one exact-size array each (and a table row is measured through scratch lists the whole table shares, keeps its cells in one exact-size array, and creates no paint box for a cell that paints nothing), a fully embedded font is compressed once per `PdfFont`, the PDF is
built in a pooled buffer, and page content streams are written straight into it
from one reused builder, with most numbers formatted in place, as are page
dictionaries, link annotations and embedded font objects (widths and the
ToUnicode map need no string per character); subsetting a font keeps state only
for the glyphs the subset reaches, not for every glyph in the font.
