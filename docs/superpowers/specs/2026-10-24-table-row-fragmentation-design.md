# Oversized body-row fragmentation

Approved for implementation on verified main `28588111d3ab453a21d9edfe4a8835efc65ed448`. Prerequisite PR #55 passed independent reviews, all19 exact-head checks and all7 post-merge workflows. Root reviewed the design and independent accounting audit; the rulings below are adopted. One implementation PR at a time.

## Contract and precedence

Add automatic splitting of otherwise unplaceable body rows to the accepted flat text/paragraph/image/colspan table model. Keep explicit tracks, one optional header row, current CSS restrictions, resource protocols and public options. No rowspan, nested table/block/list flow, automatic columns, new CSS, serializer or ordinary-block pagination redesign.

1. If the complete measured table height is at most usable height `U = PageHeight - 2*Margin` (existing 0.000001pt tolerance), retain the existing indivisible short-table path and bytes. This includes moving it intact from an occupied tail and the existing failure when required fresh ancestor padding makes that otherwise short table impossible. Ancestor pressure alone must not convert an old short table into a split table.
2. In a long table, use existing whole-row placement for every row that can fit a fresh fragment with its repeated header and required edges. A row that fits fresh moves whole when the current tail is too short. Do not split such rows to fill a tail.
3. Only a body row failing that fresh whole-row fit is eligible. This test is NOT `row.Height > U`: header, first table edges, unconsumed ancestor leading padding and terminal table bottom edges can make a physically shorter row unplaceable. Include required first edges only for the first body group, and table bottom only for the final body group (including adjacent zero-height rows).
4. A header never splits. Repeated header is a complete row above every occupied table fragment. A continued body row counts as body occupancy; no header-only fragment.

Eligibility equation for a still-whole candidate is `row.Height + H + F + L + E > U + epsilon`, where H is the header height, F the first table top edge when applicable, L the required still-unconsumed ancestor leading space on a fresh page, and E the table bottom edge when this row/group terminates the table. First and last edges may be distributed on separate fragments after eligibility is established. Preceding paragraph margin/closed-scope trailing space can disappear on moving to a fresh page exactly as today; required open-scope first padding cannot. Use `MoveUnconsumedBlocksToNewPage(apply:false)` to obtain L without mutating layout. Never use current-tail capacity to establish eligibility.

## Retained measurement and explicit interfaces

Keep `MeasuredTable`'s Runs/PaintBoxes/Images and whole `MeasuredTableRow` ranges for the unchanged fast paths. Add body-cell metadata sufficient to select immutable ranges without rewrapping or copying any suffix. A focused `src/FactsPDF/Tables/TableRowFragmentation.cs` owns new unit/cursor/fit types and pure selection; TableLayout owns measurement and TextLayout remains responsible for page/ancestor state and placement. Avoid a general pagination framework or a large new TextLayout branch.

- Append `Cells` and `CanSplit` to the measured row (header CanSplit=false). Keep `RunStart/RunCount`, `BoxStart/BoxCount`, `ImageStart/ImageCount` for whole-row/header placement. Record the cell-paint range separately from image decorations so no split cell rectangle can leak into the whole-row emission range.
- `RowContinuation(int[] NextUnits, bool IsFirstFragment)`; at most 16 cell cursors, never a list of remaining units. A per-cell index of zero means its original initial paragraph gap has not been consumed. Short cells advance once and remain at their end.

Header/table top/ancestor leading are reserved by the caller, not charged twice inside Fit.

For each yielded TextLines.Line, record `start = runs.Count`, call existing `AppendLine` with the current aligned X and negative table-local baseline, then record `runs.Count-start`, line.Height and the measured line top BEFORE advancing the enumerator. The Line.Glyphs list is borrowed and is cleared on MoveNext. Never retain Line, Glyphs or pointers into that buffer. AppendLine copies contiguous equal-style/reference-equal-font glyph groups into PlacedText strings; one line can have multiple runs, and a blank br line has zero runs but positive height. Store actual range lengths, not one-command-per-line assumptions.

Translate copied text with `newBaseline = oldBaseline + PageHeight - newUnitTop + oldUnitTop`; this is existing table-local negative-baseline geometry. Translate images and image decoration by `newUnitTop-oldUnitTop`, plus table X. Never reconstruct or remeasure text. Reuse the same PdfImage identity. Horizontal alignment and span percentage resolution stay measurement-owned.

## Measurement, finite bounds and charging

Remove only the unconditional body accumulated-height<=U checks. Keep header height/atomic geometry rejection, all resolved length bounds (finite, nonnegative, <=14,400pt), positive content width, existing track tolerance and unbreakable-width diagnostics. Validate every accumulated cell/row/table height and every coordinate sum as finite, including top += row.Height and outer width/height; do not clamp, wrap or allow infinity to reach a painter. Finite accumulated body height may exceed 14,400: that is not a single resolved CSS length and is precisely why splitting exists.

Measure/wrap every item once. Retain a metadata entry for every actual line, including br-only lines; their count remains bounded by existing input and element limits. No new public quota is needed. Check cancellation in items, lines, tracks, cursor fitting, rollback, commit, paint and repetition.

Charge retained copied text runs before AppendLine allocates them, image draws once before retention, and retained image decoration once. Preserve `ensure(1, offset)` before wrapping every text-bearing paragraph; blank-break paragraphs do not require a fake text-command charge. Repeat the header's actual runs, image draws and boxes with new charges on every repeat.

For rows proven indivisible without unresolved terminal-group context, retain today's measurement-time full-cell-box charges and command order. For a potentially splitting row, retain cell style/geometry descriptors, NOT charged full-cell PaintBoxes; charge `PaintedBox.CommandCount` on actual emitted slices only. Do not charge a full cell and later refund it, and do not charge both whole cells and slices. Compute row eligibility from measured row height, header height and fresh space before its cell rectangles are retained. Image boxes still follow all cell boxes in output. A candidate first row rejected only by ancestor pressure can be classified tentatively; if the whole table ends up short, preserve the existing indivisible rejection rather than changing it into a success. Successful old short/whole-row paths retain their exact final budget boundaries and bytes. The classification-timing section below explicitly limits the early charging/error-precedence guarantee for terminal-ambiguous rows. Final converter recount remains a consistency check, not a substitute for charge-before-retention.

The first/last-body grouping must match current TablePagination zero-height grouping when calculating required table edges. Zero-height rows cannot sever terminal table decoration or manufacture a new fragment. Positive-height margin/edge-only rows are not occupied units that can split; keep their existing whole-row behavior if they fit and fail1302 if unplaceable.

## Prefix selection, spacing and progress

Each cell independently selects the maximal ordered prefix of whole units within available body height. A next image/line may wait while other cells advance. No clipping, scaling, image segmentation, reordered flow, text wrap around images or repeated short-cell content.

Before the first split fragment, validate first-page feasibility for EVERY cell: its original top edge + original initial margin + first occupied unit must fit the fresh first body capacity. For a cell with no occupied units, its original leading/edge obligation must fit. This check precedes advancing any neighboring cell. Thus giant initial padding or a 70pt initial paragraph margin cannot vanish when a 12pt line is eventually placed on a continuation, and a short neighbor cannot manufacture apparent progress around an impossible start. If required table/ancestor first edges plus header leave no room for any atomic unit, fail1302 without producing a page.

Top cell edge is included only on the logical row's first fragment. Every first-fragment cell top edge must fit the actual selected fragment area, even if that cell's next image waits. Original initial paragraph margin remains attached to that cell's first occupied unit until that unit is placed; it is never treated as a trimmable continuation gap. It may wait with that unit while other cells progress, but the original fresh-first feasibility test cannot be evaded by consuming the top edge on an earlier page. Later inter-item gaps (the max-collapse of paragraph margins) are trimmed only if their following occupied unit starts that cell's content on a continuation fragment. Preserve them when that unit follows another occupied unit in the same fragment. Empty paragraphs only fold into those gaps; they never increment the cursor themselves.

A blank `br` line is a genuine positive-height unit and qualifies as progress even though RunCount=0. A fragment containing such lines is not a decoration-only fragment. Conversely, margins/padding/borders alone never qualify a new continuation fragment. Require AdvancedUnits>0 before committing any split-row fragment. If nothing fits on an occupied page, move once to a fresh page and recompute; if nothing fits fresh, report FPDF1302 at the blocked row/unit. No retry loop that only flips an edge flag or repeats a header.

## Terminal fit and bounded rollback

Cell bottom edges occur on the final fragment of the logical row, including cells whose content ended earlier. Every cell paints the same shared fragment height. Final folded paragraph margins are terminal obligations, accounted with that cell's bottom edge; a finished cell has current-fragment occupied end zero unless it selected units here. Empty cells also contribute their remaining terminal obligation. Do not add every cell's bottom to row height: take the maximum.

For a candidate completing all cell cursors, let e_i be the selected occupied end of cell i on this fragment (including first top edge if applicable), t_i its terminal margin and b_i its bottom edge. Completion height is `R = max_i(e_i + t_i + b_i)`. It fits only if `R + required final table bottom <= availableBodyHeight + epsilon`. The final table bottom belongs to the last logical body group, not every continued row. No outer-ancestor closing-padding redesign is included; existing EndBlock behavior remains, while its required leading padding is included above.

If all remaining units fit but this terminal equation does not, leave an actual last unit for the next fragment. Evaluate each cell's selected last unit as a rollback candidate; it must be that cell's final remaining unit so the other selected prefixes can remain committed. Check a fresh terminal fragment containing that reserved unit against the same max equation (other cells contribute their terminal margin+bottom, with zero occupied end). A noninitial inter-item gap is zero there; an unconsumed original initial margin is retained. Choose a feasible candidate with greatest current occupied end, tie by lowest column index. Remove that unit and its now-unattached gap, recompute the nonterminal shared height, and leave its cursor unadvanced. No copied suffix and no rescanning already emitted prefixes. At most 16 candidate checks per rollback, then either one successful rollback or a failure. If no fresh-terminal candidate is feasible, fail1302; do not emit an empty terminal page. If rollback leaves no occupied unit in the current candidate, return no-progress and perform the single fresh-page retry described above. A single remaining unit plus unavoidable terminal decoration that cannot fit fresh fails1302.

This avoids speculative commit/undo of painted pages. Image rollback moves the complete image plus its decoration as one unit. Terminal metadata may not turn a huge margin into arbitrarily many blank pages. Preflight each terminal-only obligation against fresh terminal capacity, and the combined candidate equation still controls actual completion.

Literal boundary: U=80, no header, 6x20pt lines, 1pt cell top/bottom borders. First fragment takes three lines (`1+60=61`). With 19pt final table padding, the continuation fits `60+1+19=80` exactly. With 20pt final table padding, `60+1+20=81` fails: reserve the final line, yielding page line counts [3,2,1], not [3,3,0]. The final fragment is `20+1+20=41pt`.

## Paint contract

Use existing PaintedBox IsFirstFragment/IsLastFragment flags for cells. Cell top border/padding only first; cell bottom border/padding only last; backgrounds and sides on every occupied fragment, including exhausted short cells. No horizontal rule at an internal cut. Spanned width stays fixed and does not invent an internal column boundary. Header boxes remain unsliced on every page. Image boxes remain complete.

**Continued body-cell boxes stop at the shared maximum occupied extent**, including initial top edges and, on the last fragment, terminal margins/bottom. They do not stretch to page bottom merely because there is a page break. The enclosing nonterminal table box retains today's page-bottom extension, as do existing ancestor slices. Distinguish these with different colors in the oracle. A gap after the row's occupied extent displays the table background, not cell background or side borders. Do not change ordinary whole-row cell heights or table/ancestor painting. Paint order remains table → all cells → image decoration → images/text; preserve the serializers' existing content conventions.

## Load-bearing accounting timing: no full-box credit

**Do not precharge a full cell as a presumed minimum cost of its future slices.** Approved gap trimming breaks that inequality: U80, cellA two12pt lines with100pt inter-item gap gives measured rowheight124; empty cellB has20pt top/bottom borders and1pt side borders. Two occupied row slices can be20pt/20pt with A's gap trimmed. B's whole box has4 border commands, but actual slices have only top then bottom,2 commands, because each slice's middleHeight is zero. With background, whole5 versus actual4 still contradicts prepayment. No credit/refund scheme based on full-box cost is permitted.

Classification/charging must be staged explicitly:

1. Header height is known before body measurement and its full boxes are always charged normally. Pass fresh required first-ancestor leading from TextLayout; resolve table top/bottom before body rows. For a body row that fits even with any still-possible terminal table bottom, it is certainly whole: charge its actual full-cell boxes after that row exactly as today.
2. A body row that cannot fit fresh even without terminal bottom is certainly eligible in a long table: keep cell descriptors, never a charged or uncharged retained full-cell PaintBox. A short-table ancestor-only candidate still follows the existing short-table rejection gate.
3. A body row that fits without table bottom but fails with it is **terminal-ambiguous** until its trailing zero-height group is resolved. Retain styles/geometry/unit descriptors for that group's cells, not full-cell PaintBoxes. On measuring the next positive-height row, resolve the preceding group as nonterminal, charge its actual whole-cell boxes, and flush that preceding group before proceeding beyond the resolving row. At table end, the trailing group is terminal: classify it with table bottom and either charge actual whole cells or leave eligible cells for slice placement. Do not assume that only the final source row receives terminal decoration; trailing zero rows are the reason for this stage.
4. Keep ordered per-row staging for charged image boxes and proven-whole charged cell boxes, plus descriptors for unresolved cells; flatten rows into the existing measured ranges in source order once classification is final. No deferred materialization may reorder cells after image decoration or alter old output paint order. A temporary candidate PaintBox used to calculate CommandCount is not retained until its actual charge succeeds. Source unit/run/image ranges remain stable; only the box ranges are assigned during ordered flattening. Avoid repeated list insertion/range shifting or quadratic suffix work.
5. Ensure-before-wrap checks the amount already definitely charged. If terminal cell-paint cost is unresolved it cannot be charged or counted as spent. Therefore one resolving row's wrapping/retention may occur before a deferred predecessor's paint-cost failure. Retained copied runs/images are still individually charged before allocation, pending descriptors are source-bounded, and actual deferred boxes/slices are charged before retention. This is an explicit limited change in **error timing/precedence** for terminal-ambiguous/newly splitting inputs; do not claim exact historical error order there. Existing positive exact-budget thresholds remain unchanged because total actual commands and command contents are unchanged. Certainly-whole legacy rows preserve the original early allowance check/charge order.

Add targeted tests for the4→2 counterexample (and background5→4), trailing-zero terminal classification versus a following positive row, a terminal-ambiguous predecessor followed by a text-bearing resolving row at the exact allowance, and a certainly-whole predecessor exhausting allowance before the next paragraph Wrap. Count final commands independently from emitted page records and verify no negative/refunded counter or double charging. Assert diagnostics/output preservation for deferred failures; assert exact legacy failure order only where this section guarantees it.

Concrete early-check regression: a certainly-whole first row with text A, opaque background,1pt padding and1pt borders costs6 commands (1text+5paint). With MaxDisplayCommands2 it must still fail1401 on that row before wrapping a following unsupported-font or overwide text row; delayed all-table paint would incorrectly allow1301/1302 first. The exception for terminal-ambiguous groups must not leak into this certainly-whole path.

## Adopted decisions and fixture details

Terminal margins and bottom edges follow logical-row completion. The deterministic greatest-current-end/lowest-column feasible rollback choice is adopted; do not revisit already committed pages. This may leave deliberate table-background gaps, as specified by occupied-extent cell painting. Original initial margins remain attached until the cell first places a unit. Certainly-whole accounting remains unchanged; terminal-ambiguous groups may expose a different first failure while preserving exact positive budgets and destination state. No full-box prepayment/refunds are allowed.

For square-image literals S3/A2, use an authored32x32 RGBA PNG, with source quadrants split at16 and RGBA (240,20,40,255), (20,220,60,128), (30,50,230,0), (40,70,200,255); CSS width24pt preserves24pt square pixels. Bind it as sample. For S7, a font-size5pt/line-height1 preceding paragraph with zero margins gives the5pt prelude; A usesfont10/line-height1 and Bfont10/line-height5. These explicit settings avoid accidentally using a12pt default line.
