## 1. 目标、已有批准与本次边界

让开发者为中英双语业务报告显式提供常规、粗体字体，以标准 HTML/CSS 子集表达强调；转换成功时得到真正使用指定字体轮廓、可搜索和复制的 PDF，缺资源或缺字时明确失败。

与[已接受范围设计](2026-10-11-first-usable-release-scope-design.md)的对应关系：

| 来源 | 已接受约束 | 本设计落实 |
| --- | --- | --- |
| §3 强调、错误/资源与兼容 | 常规/粗体角色；不伪造；明确缺失错误；旧调用兼容 | 两条显式有序链、严格角色内回退、增量 API 提案与失败契约 |
| §7 工作包 C | 粗体与列表独立验收，设计/验收先于实现 | 这里只设计 C1 粗体；列表留给独立后续设计 |
| §8 批准边界 | 新字体公共接口仍须审阅；页面和发布批准独立 | 本文 API/语法/新诊断均为提案；不把设计写成支持声明 |
| [支持矩阵 T-bold](../../acceptance/support-matrix.md) | 当前仅验证不支持的输入被拒绝 | 原探针仍期望 `FPDF1102`，本文不改当前结果或完成率 |

范围稿中“仅 A 获执行授权”是历史状态；当前授权已接续至完成 B2 后的 C1 **设计交付**。这不等于 C1 实现获批。常规文本、混排、换行、分页、字体子集与输出保护沿用已有引擎约束；不新增斜体、列表、字体家族匹配、全字重轴、可变字体、系统字体发现、网络发现或浏览器排版。标题仍沿用原字号默认值，不自动变粗。

## 2. 方案选择与唯一待决事项

| 方案 | 做法 | 代价与判断 |
| --- | --- | --- |
| **A：增量双链（推荐）** | 保留 `PdfOptions.Fonts` / `--font` 作为常规链；增加 `BoldFonts` / `--font-bold` | 旧调用不迁移，角色与顺序清楚；只解决两种角色，未来更多样式需另设计 |
| B：统一角色资源描述 | 新建角色描述集合，旧 `Fonts` 作为适配入口 | 扩展性较高，但带来两套配置的冲突/优先级及更多公共类型，超出最小目标 |
| C：按家族配对常规/粗体 | 每个显式家族绑定两张字形面，再按家族回退 | 需要家族身份、配对缺失和匹配规则；本次不需要该复杂度 |

**D1，唯一需要用户决定的项目：是否接受方案 A 及本文的对外契约作为 C1 的设计基线？** 这项决定包括新增 `BoldFonts` / `--font-bold`、§4 的有限语法和 §6 的缺失诊断。若否，只需指出希望调整的契约；不要求用户挑内部类名、缓存结构或测试工具。接受本设计不自动启动实现，也不批准页面参考、性能预算或发布。

真实静态粗体字体的来源、指纹与许可记录由后续工程验收收集；本次不要求用户购买或上传字体，不下载、打包或分发字体。找不到合规且覆盖中文的真实粗体资源时，相关验收必须阻塞，不能用常规中文字体替代。

## 3. 显式资源与入口提案

以下名称是**拟议接口，不是当前可运行用法**。转换主入口及 `PdfFont.LoadTrueType` 不变；字体对象仍不可变且可复用，角色由一次转换的配置指定，不修改字体对象的全局状态。

```csharp
// 提案：latinRegular/cjkRegular/latinBold/cjkBold 均已通过现有加载器加载。
var options = new PdfOptions {
    Fonts = [latinRegular, cjkRegular],
    BoldFonts = [latinBold, cjkBold],  // 拟新增 IReadOnlyList<PdfFont>，默认空
    SubsetFonts = true
};
using var output = new MemoryStream();
var result = PdfConverter.Convert(html, output, options);
```

```sh
# 提案；这些字体路径不随仓库提供，当前 CLI 尚不识别 --font-bold。
FactsPDF.Cli report.html report.pdf \
  --font Latin-Regular.ttf --font CJK-Regular.ttf \
  --font-bold Latin-Bold.ttf --font-bold CJK-Bold.ttf --subset-fonts
```

规则：

1. `Fonts` 是常规链，`BoldFonts` 是粗体链；每条链各自保留声明顺序。链不要求同长、同名或一一配对。中英两种角色分别完整覆盖需要的文字。
2. 先确定文本角色，再在**该角色链**中按 Unicode 标量选择第一个有字形的字体。不得因粗体链缺字而查常规链，反向也不允许。不得查文件名、系统字体、浏览器 CSS 字体或远端 URL 来补缺。
3. 两链皆空保留现有 ASCII/Courier 常规模式。提供粗体链时必须同时提供非空常规链；否则是配置错误，即使文档只含粗体也一样。这样不新增内置 Courier 与嵌入字体混用路径。没有粗体链且文档只需要常规角色，仍正常成功。
4. 两链合计至多 **8 个声明项**，在去重之前计数；常规旧调用的 8 项容量不缩减。`null` 集合、`null` 项或总数超限是参数错误。总字节额度仍使用 `MaxTotalFontBytes`（默认 64 MiB），按两链中唯一 `PdfFont` 对象合计一次；独立加载的相同字节对象仍按多个对象计。单次加载上限仍为 32 MiB。不通过拆角色翻倍额度。
5. 转换开始时分别快照两链；不允许调用方在快照期间并发修改集合。角色解析缓存必须区分角色与标量，不能让常规文本缓存污染后续粗体。同一对象在两链出现可共享嵌入资源；不同对象不能只凭 PostScript 名称合并。
6. 角色是调用方的显式声明。引擎不按字体名称或字重元数据猜角色，也不替调用方判断两款字体是否设计上匹配。把常规字体放进粗体链不会被引擎加工变粗，且不能作为“真实粗体”验收证据。验收使用经独立核对的真实常规/粗体静态字体。
7. CLI 的 `--font` 与 `--font-bold` 可交错，各自的出现顺序就是该链顺序；加载按命令行声明顺序。空路径、缺参数和 `-` 字体路径继续拒绝。输出路径不得等于 HTML 或任一角色的字体路径；`--overwrite` 不解除该保护。现有可信工作目录/文件别名限制不扩大为恶意文件系统沙箱。
8. WASM 只扩展**私有测试宿主**以传入两条显式字节链，调用同一 .NET 核心；保留原双字体参数调用的常规映射。宿主负责显式资源读取，转换器不读取 URL；这不是公开 JS SDK 接口设计。旧 B1/Node 子进程入口不改称字体 SDK。

## 4. HTML/CSS 的有限语法

| 输入 | 提议语义 |
| --- | --- |
| `<strong>…</strong>`、`<b>…</b>` | 新增行内容器，默认粗体角色；允许嵌套 `span` / `b` / `strong` / `br` 和文本；沿用合法块/行嵌套约束，不容许里面嵌块元素 |
| `font-weight: normal`、`400` | 常规角色 |
| `font-weight: bold`、`700` | 粗体角色 |
| `inherit` / `unset` | 继承父元素计算角色；`font-weight` 为继承属性 |
| `initial` | 常规角色；不会恢复 `<strong>` 的粗体默认值 |
| `!important`、内联/内嵌样式表、已有选择器 | 复用既有逐属性层叠，不新增选择器和样式来源 |
| `bolder` / `lighter`、其他数值、百分比、函数、`revert` / `revert-layer` | 本子集不支持，明确 `FPDF1202`；不做邻近字重匹配 |

数值只接受一个无单位 CSS number token，其数值必须恰为 400 或 700（例如 `400.0` 与 `400` 等价）；不接受 `400px`、多值或函数。关键字采用现有 ASCII 大小写处理。属性适用于现有可承载文字的容器、段落/标题和行内容器；`br` 不可直接设置样式，head/title/meta 仍不呈现。未知/不合法 CSS 继续严格拒绝，未命中选择器中的非法值也不能静默忽略。

无作者声明时，`b` / `strong` 使用绝对粗体角色；重复嵌套不会再加重。作者声明可覆盖，例如 `<strong style="font-weight:normal">` 使用常规链；普通子 `span` 继承，`initial` 可恢复常规。`h1`–`h6` 不新增粗体默认值；无新语法的旧报告外观保持不变。

标准边界必须公开说明：CSS 将 normal/bold 对应到 400/700，并定义继承；完整 CSS 还支持其他权重与相对权重。[W3C CSS Fonts §2.2](https://www.w3.org/TR/2026/WD-css-fonts-4-20261016/#font-weight-prop) HTML 默认呈现建议为 `b` / `strong` 使用相对加重；本提案刻意限定为两角色的绝对粗体，也保留现有标题默认值，不能宣称完整浏览器字重或默认样式兼容。[WHATWG HTML 呈现规则](https://html.spec.whatwg.org/multipage/rendering.html#phrasing-content-3)

斜体 `<i>` / `<em>` 仍为不支持元素，`font-style` 仍为不支持属性；`font` 简写、`font-family`、`@font-face`、字重轴、字体合成控制属性均不在本次范围。

## 5. 排版、嵌入与兼容不变量

- 宽度必须来自最终选中的真实字形 advance；不能先用常规宽度排版再换粗体，也不能增加描边、错位重绘、拉伸或位图来假造粗体。
- 行内容器边界不插入空格或新的换行机会：`<span>oper</span><strong>ation</strong>` 仍是连续单词；中英分段、NBSP、CJK 标点和不支持塑形的规则不扩大。
- 延续现有行盒模型：每个计算样式用**其角色链首字体**的指标及既有 line-height/leading 形成度量；行内各样式和段落 strut 共同决定行高/基线，不能把每个 CJK 回退字体的度量改成全行度量。只含常规角色时必须保留旧坐标。真实样本仍须检查不同字体轮廓有没有重叠或截断。
- 参与一行排版的粗体段落 strut 也需要粗体链，即使其中子 span 都覆盖成常规；没有文字且不形成行盒的空 `strong` 不要求加载粗体。空白沿用现有规则：段首被忽略的空白不解析字体；正文后的待定空格按原位置/角色解析，即使后续被行尾或 `br` 丢弃。缺字体诊断不能为了跳过空白而悄悄改变旧行为。
- 每个实际使用的字体对象继续使用 Type0/CIDFontType2、真实宽度和 ToUnicode；未使用对象不嵌入。全嵌入保留输入字节；子集模式按实际使用字体分别处理并保留文字映射。禁子集字体继续全嵌入；许可、结构、字形容量和输出额度仍检查。
- 无新标签/声明且 `BoldFonts` 为空的旧 .NET / CLI / 私有 WASM 调用，默认值、字体顺序、错误类型/码及同环境 PDF 字节保持一致。新增粗体对象但未使用时，不应改变成功旧文档的 PDF 字节；资源配置本身仍必须合法并计入额度。
- 从“旧版不支持”到“新版粗体成功/缺资源报错”的变化是**明确的新增输入域**，不要求 `<strong>` 永久返回旧 `FPDF1102`。设计阶段则不得提前更改这一当前断言。

## 6. 错误与失败输出契约

下表中 `FPDF1507` 是建议新增且在当前基线未占用的代码；它只有设计获批且实现后才成立。新增缺角色错误应定位到首个需要该角色的文本所在元素或段落 strut 的起始标签（HTML `SourceOffset`）；缺字错误保留 `FPDF1504`，补充角色及 `U+…`，有同一元素锚点时提供位置。字体加载错误无 HTML 源位置时仍允许 `-1`，不伪造精确字节位置。

| 单一错误输入/资源 | 核心或宿主结果 | 输出要求 |
| --- | --- | --- |
| 排版需要粗体，但粗体链为空（包括 fontless ASCII 的粗体） | **拟议 `FPDF1507`**：明确缺少 bold 角色；不给 Courier-Bold/常规回退 | 无 PDF |
| 粗体链存在但缺某字，常规链有该字 | `FPDF1504`，标出 bold 和标量；反向缺字同理 | 无 PDF |
| 两链为空的普通非 ASCII 文本 | 保留 `FPDF1301` | 无 PDF |
| 格式损坏/表示不支持/额度/嵌入许可/子集错误 | 保留 `FPDF1501` / `1502` / `1503` / `1505` / `1506`；未使用但显式提供的非法字体仍会在加载阶段失败 | 无 PDF |
| 非法角色配置（含只给粗体不给常规） | .NET `ArgumentException`；CLI 退出 2；私有 WASM 宿主拟用 `B2_INPUT_FONTS` 表示同类配置错误 | 无 PDF |
| 显式字体文件不存在/不可读 | CLI 现有 I/O 退出 4；宿主保留原 I/O 原因，附角色/条目上下文 | 无 PDF |
| 私有 WASM 显式 URL 的 HTTP 失败/选中资源为空 | 保留宿主 `B2_RESOURCE_HTTP` / `B2_RESOURCE_EMPTY`，附角色；不能冒充核心 `FPDF1507` | 无 PDF |
| 非法 font-weight / 斜体或其他仍不支持语法 | 既有 `FPDF1202` / `1201` / `1102`，按单例精确断言 | 无 PDF |
| 粗体真实宽度使词段超宽；页数/显示命令/输出额度超限 | 保留 `FPDF1302` / `1303` / `1401` | 无 PDF |

所有核心 `FactsPdfException` 在 CLI 仍退出 3，成功 0、取消 130；私有 WASM 保留原核心 code/message，不转换成通用“失败”。共享核心输入一致时，错误码与角色/标量信息一致；文件系统/HTTP/参数错误按入口分类，不能要求它们伪装成相同核心错误。多重故障输入不新增全局错误优先级承诺；验收用隔离的单故障案例。

“失败不留半成品”的准确范围：

- **字体、语法、布局、资源上限或序列化失败，在最终复制之前：** .NET 调用方输出流内容和位置不变；CLI stdout 无 PDF 字节；CLI 文件不存在时不留下新目标，已有目标即使 `--overwrite` 也逐字节不变，临时文件清理；WASM 返回失败且 `pdfBase64` 为空，不复用上次成功 PDF，也不触发下载。
- **最终复制期间的 I/O 错误或取消：** 任意 .NET 输出流/CLI stdout 可能已收到前缀，现有 API 无法回滚；不能扩大为事务输出承诺。需要文件原子替换时使用 CLI 临时文件路径或调用方自行缓冲。CLI 的最终目标仅在转换完整成功后替换；清理/重命名失败要如实报告，不把可见目标截断。
- 成功后失败、失败后成功和交替角色的并发转换均不得串用字体映射或上次结果；取消仍是已有协作取消，WASM 同步调用不因此获得新的取消/响应性保证。

## 7. 验收输入与独立断言

以下是**未来验收案例规格，不是已经运行的测试结果或已批准的页面参考**。全部使用合成业务数据。真实字体的版本、来源、许可说明、文件 SHA-256、角色和链内顺序必须先记录；至少有独立核对过的 Latin Regular/Bold 与 CJK Regular/Bold 静态 TrueType 字体，格式符合现有 `glyf` 加载器。不得把 B2 的常规 CJK 字体标成粗体，或用合成矩形测试字体代替真实页面审阅。

### 7.1 可审阅的双语简报与分页正文

```html
<!DOCTYPE html>
<html><head><meta charset="utf-8"><style>
  body { font-size: 12pt; line-height: 1.5; }
  .panel { width: 190pt; padding: 8pt; border: 1pt solid #1d4568; }
  .emphasis { font-weight: 700; }
  .next { break-before: page; }
</style></head><body>
  <h1>2026 年 10 月运营简报 / Operations brief</h1>
  <section class="panel">
    <p>本期交付 <strong>128 份报告 / 128 reports</strong>，
       <b>准时率 98.4%</b>，较上期增长 <span class="emphasis">12.5%</span>。</p>
    <p>客户备注：<strong>北京团队确认，café 服务正常。</strong>
       Reference <span>oper</span><strong>ation</strong> is searchable.</p>
    <p><strong>重点：<span style="font-weight:normal">常规补充</span>仍为重点。</strong></p>
  </section>
  <p class="next">第二节 / Section two：<strong>待办 3 项 / 3 actions</strong>。
     负责人：林晨 Lin Chen。不得遗漏或重复内容。</p>
</body></html>
```

固定 A4 与 36pt 页边距；同时运行全嵌入与子集模式。明确分页处必须另起一页。最终总页数、每行位置和页面参考要在固定真实字体下经独立检查、逐页审阅后冻结；不在设计中假定此例一定只有两页。文本预期按手工定义的文本块/源标量及原有空白折叠生成，不能从待测 PDF 反推答案。

自然跨页案例单独使用一个跨页 `.panel`，按 001–060 顺序放入以下 60 段，`NNN` 为三位编号：

```html
<p>记录 NNN / Record NNN：<strong>复核通过 / Review approved</strong>。
   本项包括北京团队的质量核验与交付确认，reference café-NNN；
   <span style="font-weight:bold">次日跟进 / Follow up tomorrow</span>。</p>
```

该例不含显式分页，要求实际跨页、窄栏内真实换行、连续面板边框正确，每个记录 ID 恰出现一次且顺序不变。再以一个 `<strong>` 包裹由同一句“北京团队复核通过 / Review approved，café 服务正常。”重复 80 次组成的长段落，验证同一粗体 run 本身跨行并跨页；重复次数和人工预期文本写入 manifest。若固定字体/几何下没有发生目标换行或跨页，案例失败，不能算覆盖。

| C1-01 | §7.1 双语简报，四个真实字体资源 | 正常/粗体中文、Latin、数字、é 均可读；强调段实际使用粗体字体资源；没有合成加粗 |

| C1-03 | 同字按常规→粗体→常规交替；覆盖/继承/initial/unset/important；嵌套 strong | 角色序列正确、无缓存污染；嵌套不升级到第三字重；重置后恢复常规 |
| C1-04 | 60 记录自然分页与 80 次重复的单粗体长段落 | ID/句子不丢不重；跨页前后角色保持；边框、行高及可视字形无重叠/截断/额外空页 |
| C1-05 | §7.1 显式分页，跨角色连续单词、NBSP、CJK 标点 | 分页语义和原断行约束不变；不能在 oper/ation 角色边界人为断词或插空格 |
| C1-06 | 同环境、同字体/顺序的旧 B00/B01/B03 和现有字体/样式案例 | 新实现与基线常规输出字节相同；仅添加合法未使用粗体链也相同；旧签名/默认值仍可用 |
| C1-07 | 有常规链但无粗体链；完全无字体的 ASCII strong；粗体段落 strut | `FPDF1507`，有元素源位置；空 strong 不误报；覆盖成 normal 且无粗体 strut 时成功 |
| C1-08 | 粗体链只覆盖 Latin，普通链覆盖中文；再做反向缺字 | `FPDF1504` 标出角色和中文标量；禁止跨角色补字 |
| C1-09 | 粗体链内首项缺字、第二项有字；共享字符能区分字形/advance | 在粗体链按序正确回退；普通链顺序不受影响；同名不同字体对象不被混淆 |
| C1-10 | `bolder`、600、700px、斜体、font-family 各自隔离输入 | 分别按 §6 精确拒绝；未命中选择器中的非法值也失败 |
| C1-11 | 缺文件/HTTP/空字节/损坏字体/禁止嵌入；错误放在粗体资源 | 区分加载与核心错误；不因未用到资源而将非法已加载字体计为成功 |
| C1-12 | 8/9 声明项、总字节额度两侧、非法配置、粗体导致超宽/页数/输出超限 | 保持准确限制与原错误类别，不给每角色另开额度；1 个故障 1 个断言 |
| C1-13 | 每类失败写往不存在文件、已有哨兵文件、MemoryStream、stdout、WASM；先成功再失败再成功 | 按 §6 检查字节/位置/目标目录临时文件/响应；原成功内容未被半成品替换，不泄漏上次结果 |
| C1-14 | 全嵌入与子集、不可子集字体、并发不同角色配置、取消 | 文字和几何一致；嵌入/子集许可正确；字体身份/资源 ID 不串用；不宣称任意流回滚 |

### 7.3 防止“看起来更黑”冒充真实粗体

每个成功案例必须同时满足：

1. qpdf 结构检查；PDF 实际文字资源可映射回 manifest 中该角色/序号的字体。全嵌入核验恢复字节 SHA-256；子集使用独立字体工具核对来自指定字体的字形轮廓、advance 与字符映射，不要求子集哈希等于完整字体。
2. 解析 PDF 文本绘制确认字形对应所选嵌入字体，未用额外描边、错位重复绘制或图片代替文字。只比较 `BaseFont` 名称、黑像素数或一个输出哈希都不足以通过。
3. Poppler 提取的文本与人工预期文本块/标量顺序一致，含所有中文、数字、é、记录编号；正反跨角色边界不增删字符。检查 ToUnicode；实际 PDF 查看器中搜索并复制整句及跨强调短语，核对粘贴结果。自动提取不替代这一交互检查，也不宣称 tagged PDF/完整无障碍支持。
4. 检查文字 bounding boxes 与已批准几何参考；逐页打开全部原始栅格，检查粗体识别、换行、基线、行间距、边框和分页。真实 PDF 生成与页面参考批准分开记录，未人工批准保持 `pending-review`。不能从本次引擎结果自动冻结真值或放宽全局差异阈值。

## 8. CLI / .NET / WASM 一致性与退出门槛

同一案例在三个入口使用相同 HTML UTF-8 字节、字体字节、**角色与链内顺序**、页面配置及 SubsetFonts；.NET 字符串对应同一 Unicode 输入。资源 manifest 逻辑上是 `regular: [id…]` 与 `bold: [id…]`，只用于验收，不宣称新增生产 JSON API。

| 层次 | 一致性要求 |
| --- | --- |
| 共享转换 | CLI/.NET/真实浏览器 WASM 都调用同一核心，禁止 DOM 排版、服务器代生成或其他引擎替代 |
| 成功 | 同环境/同工具链确定性要求 PDF 字节一致；当前受控 CLI/WASM 对照也维持字节相等门槛。跨 OS 的比较另记录平台基线，并始终要求预期文字、字体角色、页数与几何一致，不用单一跨平台哈希代替所有断言 |
| 失败 | 核心故障的 code、角色/标量及源位置契约一致；参数与资源加载按入口映射，退出码见 §6；每端验证无半成品和恢复 |
| 浏览器宿主 | 指定最终源码 SHA，真实 WASM 资产和浏览器运行证据，保留既有保护策略；受限本地环境不能改策略绕过，远端 CI 必须标明地点。C1 未来验证新角色能力，不重做/冒认 B2 已完成的基础结论 |
| 证据 | 源码与构建/运行环境、输入/字体/产物哈希、原始 PDF/文字/bbox/逐页 PNG、字体检查记录、失败报告、人工页面/复制验收状态全部可追溯 |

后续实现的完成条件：D1 设计确认 → 单独实现计划与执行授权 → C1 正反案例真实通过 → 独立代码审查与逐条处理意见 → 正常合并/远端核验。CLI/.NET 必须是真实调用，WASM 必须是真实受保护浏览器；编译通过、Node 托管替代、expected-error 或跳过均不能算角色能力通过。未具备环境/真实粗体字体/人工页面证据时，记录具体阻塞，不能把它计入成功。

T-bold 当前的 `FPDF1102` 探针保留为历史不支持证据；只有新实现及独立断言获验收后，才更新当前版本的 T-bold 输入/资源、成功判定和支持矩阵，并保留旧 SHA 对应结果。C1 案例可作为 T-bold 的明细，不另把目标分母膨胀以制造完成率；T-list 及其他目标不随之宣布完成。
