## 1. 已确认方向与事实基线

保留一套无浏览器排版依赖的核心，输入使用标准 HTML 和明确支持的 CSS 子集；不同语言通过适配层接入同一引擎。快速启动、低资源占用、AOT 和跨平台分别需要运行证据，普通 Windows/macOS 测试不等于这些平台的 AOT 或 WASM 已交付。[S1][S2]

M12 已有库 API、CLI、显式 TrueType 字体与简单横排 Unicode/中文、字体子集、嵌套块级布局、背景/实线边框和跨页片段。列表、链接、粗体/斜体元素、图片、表格、完整页眉页脚和其他语言绑定仍未支持或未实现。字体支持不是完整塑形、双向排版或所有文字系统支持。[S1][S2]

M9–M12 的资源控制和分配优化作为回归基线；不等于全流程流式处理、恒定内存或峰值进程内存保证。长段落分配实验和端到端基准分开，旧固定基线不得改名为新版本对照。[S3]

后续以用户能力、可检查交付物、验收门槛及排除项决策，Mxx 只用于跟踪。

## 2. 首版定位与用户旅程

**Developer Preview 1：面向开发者的中英双语业务报告引擎。** 名称表示受控场景预览，不是 1.0、稳定 API、生产 SLA 或公开发布授权。

报告需要标题、摘要、强调、列表、面板、少量静态图片、固定列宽明细表与可预测的多页输出。合成数据不绑定真实客户或某个房地产项目。单据与图文说明书是扩展样本，不扩展成财务计算引擎或通用出版系统。

调用方完成模板填充和业务计算，FactsPDF 接收已经生成的 HTML/CSS 与显式资源，只负责排版及 PDF。用户旅程：取得指定构建 → 按 CLI/.NET 示例提供输入和资源 → 得到可阅读、可搜索、可复制的 PDF → 不支持输入有可定位错误。独立接入者不需要隐藏配置或作者手工改仓库。

已选报告场景驱动、较早验证接入风险的路线；不采用无限微优化，也不一次发布所有语言/平台。

## 3. 已接受的能力边界（不是当前支持声明）

| 能力 | 预览版范围 | 排除项 |
| --- | --- | --- |
| 已有排版 | 当前 HTML/CSS、Unicode/中文、块布局及跨页绘制 | 任意网页截图、完整浏览器兼容 |
| 强调 | 显式常规/粗体字体角色、明确缺失错误、不伪造粗体 | 自动发现、复杂匹配、全粗细轴；斜体另行排期 |
| 列表 | 十进制有序列表、无序列表、最多两级嵌套，标记换行/分页正确 | 任意计数器、图片标记、全部列表 CSS |
| 图片 | 显式静态 JPEG、纵横比与资源边界 | PNG 为独立后续阶段；透明图、SVG、动画、自动 URL 抓取 |
| 表格 | 固定列宽、分离边框、单元格换行，先单页再整行分页/重复表头 | 自动列宽、跨行/跨列、嵌套表、跨页拆单元格；过高行明确拒绝 |
| 分页 | 显式分页、标题随首段、受控页眉页脚与页码 | 完整 @page、浮动、脚注、通用孤行算法 |
| 错误/资源 | 支持矩阵、可用源位置、额度、失败前不输出 | 完整恶意输入沙箱 |

JPEG 优先是已接受的首批限制，不意味着无需解码设计。若增加透明 Logo/PNG，须单独记录范围变更。新图像子系统必须定义压缩长度、尺寸、像素数、解码后大小、色彩/方向和取消边界，没有可验证方案不能通过放宽限制声称完成。默认不增加运行时依赖；必要例外单独审阅。

字体角色可能扩展显式资源描述，但现有调用保持兼容。精确公共 API 及新内容语法留给各子系统设计，不在范围稿中杜撰接口。

## 4. 接入与平台

首条交付路径为 **CLI + .NET 库**。本地产物/安装验证和公开 NuGet/npm/二进制发布分开，后者仍需仓库发布门槛与明确授权。[S1][S2]

首发 Native AOT 目标为 **Linux x64 与 Windows x64**。Linux 在当前基线已有真实证据；Windows AOT 是新增目标。macOS 保留普通测试，macOS arm64 AOT 后续排期。未实际构建、运行、检查输出前不能声称验证。

工作包 B 较早顺序执行两个有明确范围的探针：
1. TypeScript/Node 经 CLI 使用同一核心：验证 UTF-8、PDF 字节、显式资源、退出码、超时/取消和并发隔离；如实称子进程适配，不称原生内存调用或已发布 SDK。
2. 浏览器 WASM 宿主：同一核心与显式资源产生有效 PDF，记录构建模式、装载、大小、启动、内存和限制。浏览器仅为宿主，不用 DOM/浏览器排版、不通过服务器代生成、不换引擎，不以空模块算成功。

WASM 探针在大量新内容开发之前；失败须给可复现原因和接口/范围影响，不能伪称支持或默默无限延期。WASM 正式交付不默认和首版一起发布。Rust/Go/Python 保留后续路线，只接入共享核心。

## 5. 文档验收集

A 先建立基线，不改引擎：
- **baseline** 只使用 M12 支持能力：固定输入、配置、有序字体指纹、PDF/文字/页面图与环境；持续回归。
- **negative** 单独验证超宽、零宽、页数、输入/元素/深度、CSS、显示命令、输出大小及非法 UTF-16；适用入口和准确错误按例明确，不发明生产 CLI 参数。
- **target** 记录强调、列表、图片、表格和页码等未实现需求；expected-error、skip 和 blocked-design 都不计入功能完成。未定义 API 可以不生成假输入，但目标仍纳入分母。

| 案例 | 检查内容 |
| --- | --- |
| 双语简报 | 标题、中英正文、信息面板；文字不丢、字体/颜色/边界正确、逐页审阅 |
| 完整报告目标 | 各新能力独立断言，组合后无重叠/截断/幽灵页 |
| 10/30/100 条记录 | ID 顺序不重不漏；当前段落样本不是表格支持；目标表格另测 |
| 长报告/极限 | 正常成功，异常在准确边界失败且不写半成品 |
| 跨入口/平台 | 相同输入的文字/几何一致，同环境确定性；差异有证据解释 |

精确页数和坐标必须在实际生成后，经独立检查与真实页面审阅冻结，不能把待测引擎输出自动抄成真值。参考采集与批准分开；未获用户页面审阅则保持 pending-review。

复用 qpdf、Poppler 和 Chrome 独立验证。位图差异不替代文字/几何检查，不设置掩盖错误的宽松全局阈值。同字体/工具链基线要求字节一致，跨系统采用明确平台基线，不以全平台同哈希作为唯一标准。字体只记录授权来源/指纹，不分发字体文件；模板、合成数据和允许分发的图像可进入样例包。

## 6. 性能与发布验收

分别测冷启动、热转换、累计托管分配、进程峰值、输出大小与任务隔离。输入/资源加载/布局/序列化尽量分段，公共 API 不暴露的内部阶段标未测量，不为本验收工作改引擎。

固定提交、构建、机器/系统、字体/输入/工具及原始样本。每批至少 10 个独立进程冷启动与 30 个热转换，重复批次。每个同步热转换用 `GC.GetAllocatedBytesForCurrentThread()` 前后差值记录托管分配，测量范围是同线程转换及输出缓冲，资源预加载在外；字体加载另计。它不是总线程分配、峰值/RSS或时间指标。样本缺失不能补 0，汇总从原始数据重算。共享 CI 时间仅作 provisional 观察，不虚称固定参考机器。

绝对延迟/RSS/QPS 预算、固定参考硬件和页面审批尚未获批；A 输出实际数据和有依据的候选预算供审阅。未批准或未通过时不得宣传超高性能已达成。后续优化必须指出负载、瓶颈、收益指标及兼容性代价。

预览版需目标报告实际成功、错误路径、独立检查、目标平台、干净环境接入、支持矩阵及已审阅性能预算全部满足。已有测试数量、PR 绿色或截图不能替代。
